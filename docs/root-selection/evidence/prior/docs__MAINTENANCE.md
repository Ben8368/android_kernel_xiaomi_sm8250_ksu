# Maintenance — design and outstanding work

The default `lineage-24.0` was identical to official upstream when inspected. Do not force push, reset a public branch, or drop KSU commits. Neither scheduled synchronization nor PR automation exists yet.

Two schedule designs: A adds only reviewed automation files to the default branch, so its commit history and tree are no longer identical to upstream even though kernel business code remains untouched; GitHub scheduled workflows must exist on the default branch. B uses a separate automation repository and keeps the tracking branch pure, but requires separate repository administration and scoped credentials. A is simpler; changes to the default branch must be reviewed in a PR. No option has been deployed. A safe implementation must record before/after SHAs, verify divergence, use merge commits or reviewed PRs and report conflict paths without force-push. It must explicitly cover both upstream-to-tracking and tracking-to-KSU transitions; branch protection and token permissions need separate review.

Manual update design: fetch official LineageOS `lineage-24.0`, verify both heads and history, merge it into a review branch based on the tracking branch, review changes then merge by PR. Next merge the updated tracking branch into a review branch based on `lineage-24.0-ksu`, inspect conflict files with `git diff --name-only --diff-filter=U`, resolve and test, then create a PR into the KSU branch. Abort rather than guessing. Conflicts are not automatically resolved. For rollback, use reviewed `git revert` commits (including a correctly selected mainline parent for merge commits), after confirming dependencies; do not rewrite published history.

KSU is pinned as a git submodule. Update deliberately by reviewing upstream release/source, checking out the candidate commit in the submodule, committing the gitlink update separately, and rerunning complete production build and device tests. Stage two pins official v1.1.1 and maintains explicit parent-repository patches in compat/kernelsu-next; prepare-ksu.sh replays these locally and rejects a different submodule revision. Do not update the gitlink to an unpublished patched submodule commit. The patched Kbuild performs no network fetch or source mutation. v3.4.2 is not accepted for 4.19; see BUILD.md for the audited incompatibilities and runtime restrictions.
