# Build and validation status

Status: **blocked; no production build or flashable artifacts**. The actual `umi` device configuration includes, in order, `vendor/kona-perf_defconfig`, `vendor/debugfs.config`, `vendor/xiaomi/sm8250-common.config`, `vendor/xiaomi/umi.config`. This was checked against LineageOS device repositories sm8250-common commit `b84fe80a52e7407c53119d2dd6507285da8090d4` and umi commit `8e115b1ed63caa3ee5c3d52df0a7bce7c27512cd`. BoardConfig requests `Image`, DTB in boot and separate DTBO. Packaging and binaries are not verified.

In WSL Ubuntu 24.04, `tools/check-umi-config.sh` invokes kernel `merge_config.sh -m`, then `make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- olddefconfig` and checks KPROBES, KSU, EXT4_FS, OVERLAY_FS and SECURITY_SELINUX. GCC is used only to investigate Kconfig; it is **not** the LineageOS toolchain, and the resulting config did not retain the original Clang LTO/CFI settings. This cannot validate production config, ABI or runtime behavior. Set OUT_DIR to retain output.

On 2026-11-04 a diagnostic `make O=/tmp/umi-ksu-config ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- -j4 drivers/kernelsu/` failed: missing `SECCOMP_ARCH_NATIVE_NR`, missing `uapi/linux/mount.h`, and missing generated SELinux `flask.h` (the latter may result from invoking a subdirectory directly). See `validation/ksu-gcc-directory-build.log`. Do not treat direct-subdirectory compilation as a complete build. The correct LineageOS 24.0 Clang version, toolchain revisions and complete build commands have not been established. A full source-tree build with those exact tools, production .config and Image/DTB/DTBO checks remains required before CI can be considered meaningful.
